## Why this study

Every earlier result in this repository comes from synthetic sessions
written by the same author as the extractor. That is the first thing a
reviewer questions, and rounds 3, 5 and 8 showed why: gains on corpora the
author had read did not carry over to corpora written later. This study
replaces that with **public, real agent traffic** and **ground truth no one
wrote by hand**.

## Ground truth (automatic)

- **Edited files.** The paths changed by the submitted patch. For OpenHands,
  build artifacts its commands left in the patch are removed by a rule fixed
  in advance; for example, one patch contains 1,096 compiled `.mo` files.
  The same filter is reported *post hoc* for the SWE-agent systems as a
  secondary metric.
- **Errors.** Read from tool observations only, never from the agent's own
  prose.
  - *Runtime*: the last line of each Python traceback.
  - *Lint*: each linter error SWE-agent reported for a proposed edit.

Twelve randomly sampled error labels were checked against their source
observation, and all twelve were genuine. Completed tasks, pending tasks and
decisions have no objective label in this data and are not scored.

## Design

- **Dev/test split by issue.** Split by `crc32(instance_id) % 2`, so all
  five systems' attempts at one issue fall on the same side. That gives 751
  dev sessions and 716 test sessions.
- **Bugs were found only on dev.** Test was never inspected session by
  session. It was scored once at `50a2952` and once at `aae16f8`, and those
  are the numbers below.
- **Conditions.**
  - *Batch*: the whole session at once, for every method.
  - *Incremental*: one message per call, which is how the proxy runs in
    production. TokenMizer only.
- **Metrics** are defined in `benchmarks/realworld/README.md`.
  - Pooled (micro) ratios have 95% session-level bootstrap intervals (2,000
    resamples, seed 1729).
  - Before/after differences use a *paired* bootstrap: the same resampled
    sessions are scored under both commits.

### Reading the results

- **Errors.** Runtime-error recall rose from 63% to 92% in batch, and to
  96% in the production (incremental) condition. It lies between 90% and
  94% for every system. Precision against the automatic ground truth
  nearly doubled, from 16% to 31%, and the share of runtime errors in the
  400-token resume rose from 20% to 50%. Every one of these paired
  intervals excludes zero.
- **Comparison methods and errors.** They recall 5–12% of runtime
  errors. Their shared error rule keeps the text after the word "Error" up
  to the first full stop, so "ValueError: invalid literal …" loses its
  class. That reflects the rule, not the memory strategy.
- **Files.** Pooled file recall: +2.2 points, with an interval that
  crosses zero. With build artifacts removed: +3.7 points, excluding
  zero. Per session, recall rose from 89% to 94%, and on OpenHands from
  78% to 96%. The gain is not uniform: 13 test sessions lost 39 recalled files while 51 gained 81. Test sessions are not read, so the cause was traced on dev, where 9 sessions lost 25 files. The agent never names any of those 25 in its own messages. They are `setup.py` and `tox.ini` changed by the environment's setup, a test directory copied wholesale with `cp -r`, and a file inside a virtualenv. The old version recalled them only because it stored every name in a directory listing as a file. They are counted as losses, not excluded.
- **Resume against a sliding window.** After the fixes, TokenMizer's
  resume carries more runtime errors (50% vs 35%) and more edited files
  (67% vs 58%) than the last ten messages verbatim, at 222 tokens against
  5,910.
- **Incremental versus batch.** Incremental extraction recalls more than
  batch, before and after the fixes. Before the fixes, one cause is
  defect 1 below, which collapsed errors within one extraction call. The
  cause of the smaller gap that remains afterwards is not isolated.

## What the dev split exposed (all fixed in PR #71)

Each fix has a regression test built from the real construction that
triggered it, and each test fails on `50a2952`.

1. **Different errors of one class were collapsed.**
   - One label was kept per exception class for a whole extraction call.
   - On SWE-agent sessions, "ValueError: Imaginary coordinates are not
     permitted" was deleted by a later, unrelated "ValueError: Error from
     parse_expr".
2. **"E + capitals" was treated as an errno name.** "YOU CAN ONLY ENTER ONE
   COMMAND AT A TIME", from SWE-agent's instructions, was stored as an error
   in every session of that framework.
3. **Traceback messages were cut** at the first dot or comma ("Model class
   `__main__`"), and qualified exceptions lost their module path.
4. **Framework text was read as failures.**
   - Instruction boilerplate: "DO NOT re-run the same failed edit command".
   - Negated mentions: "without encountering any configuration errors".
   - Code behaviour: "modify it to raise a ValueError when …".
   - Docstrings in line-numbered file views.
5. **Directory listings became files.**
   - One `ls -R` produced 906 FILE nodes; others produced hundreds. Columnar
     output with `\r\n` line endings defeated the first fix.
   - The graph's 200-node cap then pruned the files the agent had actually
     edited: on OpenHands, per-session file recall was 79% before the fix.
   - Dotted module paths ("`from django.db import models`") became files.
6. **Resume ordering.**
   - Open errors and files were listed oldest first, because every node of a
     type shares one importance and ties fell back to insertion order.
   - Files changed by a tool call now rank first.
7. **A listing regex introduced during this work was quadratic** on long
   space runs: 4–8 s on one fuzzed line. Fuzzing found it before merge. The
   linearity test now carries the reproducing payload.

## Threats to validity

- **Frameworks and language.** There are two agent frameworks and one
  language (Python). Both formats are common in production, but other
  agents, languages and non-coding sessions are not covered.
- **Error precision is a lower bound.** Three reasons:
  - The ground truth reads tool observations only. Errors quoted in the
    issue text are real, and so are failures the agent reports in its own
    words ("there was an indentation error in my previous edit"), but they
    count as spurious.
  - The ground truth's exception rule requires an Error/Exception/Warning
    suffix, so Django's `ImproperlyConfigured` and `AppRegistryNotReady` are
    missed. The rule was frozen before measurement and is not changed after
    the fact.
  - The comparison methods face the same ground truth, so the comparison is
    fair even though the absolute level is conservative.
- **Ceiling on file recall.**
  - Of 29 missed files examined in 120 SWE-agent dev sessions (before the
    fixes), 23 are never named anywhere in the conversation; the agent
    created them through scripts.
  - No memory method can recall those, and the pooled recall includes them.
- **Heavy tail.** A few patches create hundreds of files (an entire scaffold
  project). Pooled file ratios are dominated by them, so per-session (macro)
  recall is reported alongside.
- **Token counts** are characters ÷ 4 for every method. In this
  environment, the product's own resume budget also uses its
  characters ÷ 4 fallback (the tiktoken encoding cannot be downloaded
  here).
- **Latency.** The incremental runs were measured with four benchmark
  processes sharing four CPUs, so absolute per-request times are inflated;
  only the before/after ratio under equal load is meaningful.
- **Comparison methods.** The Graphiti-, Mem0-, MemGPT- and GraphRAG-style
  methods are deterministic regex reimplementations of one structural
  property each, not the vendor products (see the paper's Threats to
  Validity section).
