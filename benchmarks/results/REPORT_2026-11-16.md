### Load (`benchmarks/load` in the product repository, new)

**Setup.**
- The real server: `uvicorn tokenmizer.api.app:app`, with 1 or 4 worker processes.
- Real HTTP, with `provider=ollama` pointed at a stand-in that speaks the Ollama API.
- Sessions run concurrently and each resends its whole history; a quarter of requests stream.

**What is checked, on every request:**
- the response: status, OpenAI shape, the exact reply, and SSE ending in `[DONE]`;
- the request sent upstream: it contains the client's newest message verbatim, and no other session's marker;
- malformed requests: each gets a 4xx, never a 5xx, and the server keeps serving.

At the end, each session asks for the decision its last turn made.

| | 1 worker, 32 sessions × 30 turns | 4 workers, 48 sessions × 30 turns |
|---|---:|---:|
| Requests passing every check | 960 of 960 | 1,440 of 1,440 |
| Upstream: newest message missing / another session leaked | 0 / 0 | 0 / 0 |
| Malformed requests answered with a 5xx | 0 | 0 |
| Latest decision recalled | 32 of 32 | **48 of 48** (23 of 48 before the fix) |
| Throughput | 46 req/s | 148 req/s |
| Latency p50 / p95 / p99 | 667 / 932 / 1,096 ms | 279 / 538 / 704 ms |
| Server memory, start → end | 102 → 225 MB | 448 → 692 MB (4 processes) |

The client, the stand-in and the server share four cores, so these latencies are an upper bound.

## 4. Defects fixed this round

Each fix has regression tests that fail without it.

### 4.1 With several workers, a turn could be answered from stale memory

**Cause.**
- Each uvicorn worker cached its own copy of a session and never re-read it.
- Writes from several workers already merged safely on disk, but reads did not follow them. A turn routed to a worker saw nothing the other workers had extracted since.
- With 4 workers, 23 of 48 sessions were answered with a decision that a later turn had replaced.

**Fix.**
- The session's metadata row in SQLite now carries a write counter, added to older databases when they open.
- A worker compares that counter with its own under the session lock on every request. If another worker has written since, it saves its own unsaved changes and reloads.
- Recall is now 48 of 48, and throughput did not drop (131 → 137 req/s on the same commit pair).
- Upgrading from the last release, v0.6.1, and rolling back to it were both checked.

### 4.2 The resume depended on the wall clock

**Cause.**
- Recent facts were ranked by whole seconds of their last-update timestamp, then by importance.
- Whether two requests' facts tied therefore depended on where a second boundary fell, and so on machine speed.
- A change that made each save slightly slower shifted 18 real sessions' resumes; that is how it was found.
- Six repeat runs of 18 sessions on unchanged code varied in 15 of them.

The last report fixed the sub-second case and listed this one as open.

**Fix.** Nodes now carry two counters, both stored with the node:
- the extraction call that last mentioned them, which replaces "the same second";
- their mention order in the session.

These order the resume, the checkpoint's recently completed tasks, which decision a change of mind replaces, and the tie-break in pruning. Nodes stored before the change keep their timestamp order.

**Result.** Over two full runs in each mode, 0 of 716 sessions differ.

### 4.3 A lone surrogate in a message failed the request with a 502

A lone UTF-16 surrogate (`"\ud800"`, legal in JSON) reached the provider client, which could not encode it. Request text is now scrubbed when the request arrives, as stored text already was. Found by the load test's malformed requests.

## 5. Checks on the final code

- **Product suite:** 2,371 tests pass (3 skipped) on Python 3.11, 3.12 and 3.13, with 88% line coverage. ruff and mypy are clean.

## 6. Still open

- **Implicit wording.** Held-out v3, v3x, v4 and v4x are at 65%, 65%, 59% and 61%: pattern matching has reached its limit there. The LLM extraction path, which can run locally through Ollama, was not run in this round: no API key was available and no GPU.
- **Some changes of mind are still missed.** "Let's go the other way", which names neither the slot nor the old value, is not extracted.
- **`ho3_debug_production_001` still gets two wrong pending tasks.** They are left unfixed so as not to tune against a held-out set.
- **What stays per worker.** Rate limits, analytics and the semantic cache are still kept separately by each worker; see the product's `docs/deployment.md`.
- **No end-to-end latency through a real provider.** `benchmarks/latency` needs an API key and outbound access, neither available here.
- **Token counts use the character/4 fallback.** The tokenizer files could not be downloaded.
