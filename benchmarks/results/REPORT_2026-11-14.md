## 3. Long sessions

`benchmarks/soak` lives in the product repository. It drives the real proxy the way a chat client does, with the whole history resent each request; only the provider is a stand-in.
- The session holds 50 planted facts: 10 each of decisions, errors, pending tasks, edited files and finished tasks.
- Each fact has an answer token that appears nowhere else.
- At the end, each fact is asked about. It counts as recalled if its answer is in the request sent upstream.

## 4. Defects fixed this round

Each fix has a regression test that fails without it.

**Decisions** (both found last round and present on `main`):
1. **A decision's scope was not part of its identity.**
   - "The ledger service uses `ledger_events`" superseded "the billing service uses `billing_events`".
   - "Redis for rate limiting" replaced "Redis for caching".
   - Scope now comes from "for the X", "for <doing something>" and "the X uses".
   - Two scopes match only when one contains the other: "the quartz scheduler" and "the quartz gateway" share a word but are two components.
   - A bare reason is not a scope. "Rust for performance" → "Go for simplicity" still supersedes.
2. **A technology named in a decision's reason counted as its choice.** "…because Postgres row locks were too slow" made every such decision the same slot.
3. **Changes of mind were not read.**
   - "Switch/change the SLOT to X" and "let's … instead" extracted nothing, so the old choice stayed current.
   - They now supersede the latest decision for that slot and scope. A restatement supersedes nothing.
   - "Replace X with Y" in the imperative was never matched.
4. **A scope at the head of a sentence was dropped from the label.** "For the search service we'll use Elasticsearch" became "Use Elasticsearch".

**Memory** (found by attributing growth with `tracemalloc` over 600 turns):

5. **The message-word memo kept whole messages alive.** It was an `lru_cache` keyed on whole message texts: up to 4,096 messages, megabyte tool outputs included. It accounted for 38 MB of growth in 600 turns and was unbounded in bytes.
6. **Two more memos were capped by entry count only.**
   - The tool-output path memo held 77 MB after 300 large listings, projecting to gigabytes.
   - The redaction memo's worst case was 2 GB.

All three now use one bounded cache: digest keys, plus caps on both entries and total size.

**Determinism and speed:**

7. **The resume ranked recent tasks by `updated_at * 0.6 + importance * 0.4`.** `updated_at` is a Unix timestamp, so importance never counted, and the order followed the clock's resolution.
8. **A prefix-less error-header regex ran on all tool output.** It took 45 ms per 64 KB with nothing to find. It is now gated by its own keywords, and a test checks that no gate ever skips a match.

**Test suite:**

9. **Tests shared the repository's storage directory across runs.** Two tests failed once a hundred older sessions had accumulated there.

## 6. Still open

- **Held-out v3 / v4 are at 65% / 59%.** Pattern matching has reached its limit on implicit phrasing. The LLM extraction path, which can run locally on Ollama, could not be measured here: no Ollama, no GPU, and no access to its model registry.
- **Some changes of mind are still missed.** One that names neither the slot nor the old value ("let's go the other way") is not extracted.
- **`ho3_debug_production_001` still gets two wrong pending tasks.** They are left unfixed so as not to tune against a held-out set.
- **The resume is not fully deterministic yet.** It is ordered by whole seconds of the wall clock. Two runs whose nodes straddle a second boundary can still differ; the change fixed the microsecond-level case only.
- **`benchmarks/latency` was not run.** It measures end to end through a real provider, which needs an API key and outbound access this environment does not have. The proxy's own per-request cost is in §3.
- **Token counts use the character/4 fallback.** The tokenizer files could not be downloaded.
- **Concurrency latency is limited by one process.** Eight concurrent sessions in a single Python process reach a 95th-percentile latency of 2.5 s, because they all share one GIL.
